# Reviewed assessment copies

This source slice adds definition-only blank respondent and PRIVATE author scoring-guide DOCX downloads. It does not save editable definitions, insert content into Word, collect responses, add course schema fields, or establish assessment validity.

`prepareAssessmentExport(definition, options)` accepts exactly two arguments. `options` is an exact enumerable own-data record containing `route` (`respondent` or `author`), authored `instructions` (string, at most 16,000 UTF-16 units), `baseLanguage` (one of the existing eight supported base-language tags), and a canonical ISO `stamp`. Explicit unsupported, accessor, hidden, inherited and symbol fields refuse. Core definition validation and limits are unchanged. CRLF and CR normalize to LF only in the output projection; raw session drafts remain unchanged.

The returned new recursively frozen object has `profileVersion: 1`, `route`, `preview`, and `files`. Respondent preview and files contain only assessment title/ID/version, export instructions, item type/prompt, semantic target/endpoints and ordered labels, plus derived publication identity and blank-selection guidance. They never retain the full definition, private item/option IDs, numeric codes, reverse keys, high-score meaning or subscales. Authored public text can itself contain private content; the author must review it. Neither route has a response or result argument. The PRIVATE guide includes explicit codes, reverse direction and authored subscale/missing rules, with no response values, norms or clinical interpretation.

`assessmentExportBlob(definition, options, Zip)` accepts exactly three arguments, regenerates from the validated definition/options, and uses the unchanged `familyWorkbookBlob` strict ZIP round-trip validator. The export has seven canonical parts, the existing exact content types/relationships/settings15 constants, semantic Title/Heading1/Heading2 paragraphs, black Arial body styles, base-language defaults and core metadata. Printable `[ ]` markers are text; there are no interactive Word form controls, tables, assets, extra relationships or stored responses. Long choices can wrap and split normally. The seven-part structure reuses the existing profile infrastructure; assessment export profile1 is separate from workbook profile3 and does not change legacy outputs.

`mountAssessmentExports` receives only a validated captured definition and response-free draft fingerprint from the parent assessment controller. A pending Keep/Discard choice or unfinished/different definition blocks export. It has a separate session-only instructions/language/route draft, exact content review, review acknowledgement and additional PRIVATE acknowledgement, all initially off. Test answer changes do not invalidate export review because answers are never read by this controller. Definition/raw editor/option/route/display/consent/navigation changes invalidate or refuse stale export. Exact expected files and paragraph text are regenerated before and after async packaging. The existing ZIP helper makes private byte copies; the controller also snapshots offered Blob bytes before its final freshness guard. Failed or interrupted assembly offers no file and retains drafts and responses. Starting a new assessment retains export instructions, route and base-language drafts and explicitly discloses this; prior export review is invalidated. Repeated healthy downloads retain the reviewed generation stamp and get new UUID filenames.

Automated mock-DOM and package checks are not native keyboard, screen-reader, Word layout or accessibility qualification. Local visual rendering was not performed in this staging implementation. Cover/logo/copyright, table of contents and educational-research front matter remain separate pending work.
