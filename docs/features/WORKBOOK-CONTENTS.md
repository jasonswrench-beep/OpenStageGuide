# Workbook contents navigation extension v1

This source slice adds an optional session-only table of contents to the five-family reviewed new-workbook-copy route. It adds no new course fields, front-matter/preset migration, publication persistence, Word writes or network requests. The live family route retains its existing refresh/persist infrastructure; the new checkbox does not enter that course payload, and the whole inherited route is not claimed to be read-only. The new inclusion checkbox starts off and keeps its raw checked/value/native-validity state across section/family/scope and branding/publication changes. Reload or another document pane can lose it; the best-effort unload warning may be ignored by Word.

Canonical option: `toc: {schemaVersion:1, include:false}` is optional in prepareFamilyWorkbook and beside baseLanguage/frontMatter in renderWorkbookFamily. Omission or false preserves all accepted652 seven-part files and output preview exactly, including front-matter-enabled copies. New `workbook-contents.mjs` owns strict own-data validation and deterministic heading-roster navigation. Explicit null/undefined/unsupported fields/version/accessors/symbols/inherited or hidden data refuse without getter evaluation.

Enabled contents use the exact emitted Heading1/Heading2 roster: optional Copyright, module headings, each emitted Learning objective heading and activity headings, in document order. Cover/title/subtitle, scope/identity paragraphs and the contents heading itself are excluded. Duplicate labels remain distinct linked entries; input identity keys must be unique. Actual labels include each family's display prefixes. Selected-plan content is already filtered by the accepted semantic adapter before this roster is produced.

Entries receive document-local numeric bookmark IDs and short ASCII names derived from stable heading identities, with deterministic collision disambiguation and a final uniqueness check. Names remain stable for the same heading roster across repeated generation/family changes, not an authenticated or global cross-document identity guarantee. Bookmark ranges enclose the actual heading text. Hyperlinks use internal w:anchor only: no external relationship or fetched URL.

Order is optional cover/copyright, then contents, then scope/identity and learner content. ContentsTitle is a real heading intentionally excluded from entries; ContentsLevel1/2 are ordinary non-outline paragraphs, with validated body text color/font, underlined links and indentation for level2. Long entries can wrap/split without chaining the whole contents into one block. Styles are emitted only when included so off bytes remain exact. No new parts/assets/headers/footers are introduced.

The generated contents are navigation links with no page numbers. No TOC/PAGEREF field or updateFields setting is emitted; Word is not represented as having calculated or updated pages. Regenerate after source-heading changes. Native Word link activation, page layout, Navigation Pane, keyboard/screen-reader, Accessibility Checker and print/PDF qualification remain open.

Preview exposes the complete linked entry roster and the no-page-number limit. Existing raw/publication/source/display/consent epochs guard Apply before and after async packaging. Inclusion changes invalidate review without changing course or other drafts. Educational research and actual logo/image assets remain separate next steps.

The bounded builder accepts up to 4007 heading records, 400,000 published label units and 1,000,000 identity units (50,000 per label, 1,000 per key), separate from the underlying semantic budget. This covers the accepted 2000-node semantic maximum, optional Copyright and six research headings, repeated objective labels and family display prefixes. An empty roster yields a clear empty-state paragraph and no fabricated link. Public entries expose anchors and local numeric IDs, not raw identity keys. Enabled contents styles use the same specifications for XML and the applied-style preview; omitted/off styles and preview remain unchanged.

`validateWorkbookContents` accepts exactly one configuration. `workbookContentsRequest` accepts exactly one checkbox raw record `{checked,value,invalid}` with the ten existing validity booleans. `buildWorkbookContents` accepts one dense own-data heading roster `{key,level:1|2,text}` and returns newly frozen public entries `{level,text,anchor,bookmarkId}` without raw keys. Duplicate identities refuse. Names use two seeded 64-bit FNV streams truncated to 96 bits, deterministic code-unit sorting within collision groups and a final uniqueness check; these are navigation names, not cryptographic signatures.

Enabled hyperlink text runs explicitly set the validated post-grayscale body ink and a single underline, rather than relying on Word default/visited link colors. Font/size/spacing inherit enabled-only non-outline ContentsLevel styles. The same style-specification helper drives actual XML and applied-style preview. The human review lists entry count and indented heading text/limitations; opaque bookmark names remain in structured preview/package guards, not the user review text.
